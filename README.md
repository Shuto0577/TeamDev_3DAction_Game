## 見てほしいポイント

### 1. 焦りを見抜いて、焦り方に合わせて突いてくるボス

プレイヤーの操作から「焦り」を検知し、ボスがその焦り方に合わせて攻め方を変えるシステムです。

```
【プレイヤー側】PanicDetector … 焦りを「見抜く」
   8つの指標 → 焦り度（0〜100）→ 段階（平常 / 動揺 / 焦り）＋ 系統（何に焦っているか）
        ↓
【ボス側】TBossPanicPressure … 焦りを「突く」
   段階と系統から追い込み方を決め、攻撃間隔・攻撃の選ばれやすさ・間合いなどに補正を掛ける
```

ただ攻撃が激しくなるのではなく、**焦りの系統ごとに、その弱点を突く攻め方**に変わります。

| 焦りの系統 | 検知する指標 | ボスの追い込み方 |
| --- | --- | --- |
| 逃げ腰 | 逃避、空間喪失 | 逃げる相手を触手で引き戻し、見失ってもしつこく追う |
| 防御崩れ | 防御の連打、連続被弾 | 連打のタイミングを、防げない触手とためのある鎌で外す |
| 迷い | 弓のキャンセル、照準のぶれ、武器の空回し | 弓を構えられても下がらず、内側まで詰めて迷う時間を与えない |
| 硬直 | 攻撃が来ても何もしない | 出の速い通常攻撃を、間を置かず畳みかける |

**遊びとして成り立たせるための歯止め**

- **ハメにしない**：追い込みは最大8秒・2発までとし、必ず4秒の息継ぎを挟みます。「当たる → 焦る → さらに攻められる」の悪循環を防ぐためです。
- **合図を出す**：追い込みの開始時に、ボスの目の光と音で合図を出し、最初の攻撃まで最低0.5秒あけます。合図と同時に攻撃されると、気付いたときには手遅れで、合図の意味がないためです。
- **誤検知を防ぐ**：気付かれていない隠密行動中は計測しない、掴まれている間の電撃は「回避失敗」に数えない、剣以外の武器では防御ボタンの連打を数えない（同じボタンが弓では構え、鎌では投擲になるため）など、焦りではない操作を除外しています。

**設計**

- 8つの指標は共通の親クラス（`PanicSignal`）を持つ独立したクラスに分け、追加・削除を容易にしています。
- 毎フレームの観測値は `PanicContext` にまとめてから各指標に渡し、指標がプレイヤーの実装の詳細に依存しないようにしています。
- ボス側の判断は `TBossPanicPressure` に集約し、各ステートは補正値を掛けるだけにしています。MonoBehaviourではない通常のクラスで、時間は外から渡すため、テストから時間を進めて動作を確認できます。

→ スクリプトと各ファイルの説明：[Scripts/Panic](./Scripts/Panic)（プロジェクトからの抜粋のため、単体ではコンパイルできません）

### 2. 戦闘システム

- **4種の武器**：刀（ガード・パリィ）、弓（構え・射撃）、鎌（投擲）、ハンマー（範囲攻撃）
- **TutorialBoss**：懐中電灯の光と音でプレイヤーを発見して襲いかかる敵。ワイヤーでの拘束・引き寄せ・電撃、腕を伸ばしての鎌の2連撃などを実装
- **ステートマシン**で敵とプレイヤーの行動を管理
- **見た目とロジックの分離**：仮モデルから本番モデルへ差し替えるとき、モデルの変更だけで済むようにしました
- **調整のしやすさ**：攻撃判定や音の検知範囲、敵の攻撃挙動を、シーン上の再生機能やギズモで確認しながら調整できるようにしました

#### 攻撃案から実装へ（TutorialBoss）
 
ボスの攻撃案は、他の班が考えたものを受け取って実装しています。案をそのまま作るのではなく、案の意図を守りながら、遊びとして成り立つ形や、チームの作業量で実現できる形に調整しました。
 
| 攻撃案（他の班） | 実装 | 変えた理由 |
| --- | --- | --- |
| 通常攻撃：左腕を左下から右上に振り上げる | 案のとおり実装 | ― |
| 遠距離攻撃：左腕を伸ばし、鎌で切り付けつつ引き寄せる | 腕を伸ばして鎌で2連撃 | 受け取ったアニメーションでは意図した表現が難しく、作り直しを依頼するのも作業量的に厳しいと判断したため。他の班に相談し、案の核である「腕を伸ばして攻撃する」は守ったうえで、2連撃に変更しました |
| 特殊攻撃：右手で首根っこを掴み、電撃攻撃 | 右手のワイヤーを伸ばして拘束 → 引き寄せ → 電撃 → 脱出 | 「右手のワイヤーで掴んで攻撃させたい」という要望を受けて、掴み方をワイヤーに変更しました。掴まれたら抜け出せる操作を用意しないと理不尽になるため、『BIOHAZARD』シリーズの掴み攻撃を参考に脱出を追加し、ワイヤーの伸ばし方と掴まれた後の演出は『BIOHAZARD RE:4』のリヘナラドールを参考にしました |
| （案にはない） | 懐中電灯の光と物音でプレイヤーを発見する索敵 | 暗闇の中で戦うボスとして、他班の、光に入ると見つかるようにしたいという要望から。ただし、それだけでは難易度的に簡単すぎたのと、個人的には、さらに緊張感をもたせたいという理由で、他班との交渉の末、音で見つかるという要素を取り入れた。 |
| （案にはない） | プレイヤーの焦りに合わせて攻め方を変える追い込み | チームのテーマ「AIを用いて、プレイヤーの感情を動かす」を、ボスの行動として表現するため |
 
→ 他の班から受け取った攻撃案：[攻撃モーション](./Docs/BossAttackPlan.pdf)

## チームでの役割

システム班のリーダーとして、実装に加えて、班の中と班の間の調整を行いました。

- **得意分野に合わせた役割分担**：サーバー、CI/CD、Web、UIなど、メンバーの得意なことを発揮できるよう担当を割り振り、月ごとの計画表を作成しました。
  → [システム班の8月計画表](./Docs/SystemTeamPlan_August.pdf)
- **発表から逆算した要望の整理**：最終成果発表会に向けて、他の班に必要なものと期限を整理して共有しました。
  → [11月10日までに必要なもの](./Docs/Deliverables_Nov10.pdf)
- **視覚班へのアニメーション制作の依頼**：Blenderでのモデリング・リギングの経験を活かし、Unity側でエラーや手戻りが出ないよう、ボーンの構成や書き出し方、Unity側でどう使うかを理由とあわせて依頼書にまとめました。
  - 武器を動かすための空のボーンを手首に追加してもらう
  - 前進する攻撃もその場で作ってもらい、移動はプログラム側で行う
  - ループするアニメーションは最初と最後のフレームを一致させる
  - 弓の構えはUnity側でStart・Loop・Fireに分割するため、フレーム数が分かる形でもらう
  - 操作感のため、攻撃の振りかぶりから判定が出るまでを0.05〜0.15秒に抑える

  → [プレイヤーのアニメーション依頼書](./Docs/PlayerAnimationRequest.pdf) / [敵のアニメーション一覧](./Docs/EnemyAnimationList.pdf)
- **集まる時間の使い方**：チームで集まるときは話し合いと相談に充て、実装は各自の時間で進めました。
